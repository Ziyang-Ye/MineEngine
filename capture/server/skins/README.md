# Minecraft Skin System

This directory contains the player skins used during data collection. Every skin is a
64x64 PNG; a `<name>.png.customskin` file with pre-signed Mojang texture data is optional
(only `mode=signed` and the Docker path need one).

```
session_a.png, session_b.png            session skins of `episode start` (generate_compose.py)
catalogue.json                              index of the per-episode pool (tools/skins/build_pool.py)
pool/default_<name>_<wide|slim>.png         the 9 default characters x 2 arm models (from the 1.21 client jar)
pool/proc_NNNN.png                          procedural characters (tools/skins/generate_skins.py, seeded)
pool/*.png.customskin                       optional signed caches (regenerate_skin_cache.py --upload)
reference/<skin_id>.png                     reference sheet: front/back/left/right T-pose + texture
reference/<skin_id>_skin.png, _views.json   raw skin copy, panel rectangles
```

Field-level documentation: `windows/schema_parts/r2-skins.md`.

## Local skins (default) vs signed skins

Vanilla Minecraft clients only display another player's skin if the profile's `textures`
property is **signed by Mojang** and points to `textures.minecraft.net` (1.21:
`PlayerInfo#createSkinLookup` falls back to the default skin when the texture is not secure).
Our camera clients run the `solaris-capture` mod, which also accepts an UNSIGNED property
naming a local skin (`http://solaris.local/skins/<skin_id>.png` + a `solaris` block with the
skin id, model and PNG sha256) and renders that PNG from its local copy of `pool/`. MirrorBot
sets such a property by default (`/episode skin ... mode=auto|local`), so every PNG in the pool
works fully offline - no MineSkin upload, no Mojang download.

Signed caches are still supported (`mode=signed`, the fallback of `mode=auto`; the session
skins of `episode start` use one when it exists, otherwise they are applied as local skins).
The Docker path needs them: its camera clients are vanilla and show only signed skins.
A PNG is signed by uploading it once to the third-party
[MineSkin](https://mineskin.org) service. `regenerate_skin_cache.py` only uploads with an
explicit `--upload` flag (dry run otherwise) and no setup script calls it.

## Per-episode skins (round 2)

`controller/utils/skins.js` picks two different pool skins per episode (own seeded RNG,
identical on both bots) and the leader applies them with the MirrorBot command

```
episode skin <controller> <skin_id> [camera|-] [note=0|1]      -> {"ok":true,"skin_id","model","texture_hash",...}
episode skinstatus <player>                                    -> {"ok":true,"texture_hash","model","signed",...}
```

which also gives the paired camera player the same skin (first-person arm). By default
(native Windows and Linux runners: `skin_mode=auto`, `skin_sources=default,procedural`, `skin_require_cached=0`)
the 318 default and procedural skins are eligible and applied as local skins; the 24 held-out and the
2 session skins are drawn only when `heldout` / `legacy` is listed in `skin_sources`. `skin_mode=signed`
restores the old behaviour (SkinsRestorer + `.customskin`, only cached skins eligible) and is the Docker default
(the Docker camera clients are vanilla and cannot render local skins).

## (Re)building the pool

```bash
# PNGs, catalogue, reference sheets (deterministic; ~2 min)
python tools/skins/build_pool.py --count 300 --seed 20251023
# OPTIONAL signed caches (uploads to MineSkin!): resumable, ~60 uploads/hour without an API key
python regenerate_skin_cache.py --upload server/skins/pool --verify
# refresh the `cached` flags in catalogue.json
python tools/skins/build_pool.py --catalogue-only
# OPTIONAL, signed skins only: pre-seed the camera clients' skin download cache
python tools/skins/seed_client_cache.py --mc-home .cache/windows/minecraft
```

Use `python3` instead of `python` on Linux/macOS.

## Adding a single custom skin

1. Place a 64x64 PNG in `pool/` (per-episode pool) or here (session skin).
2. Only for `mode=signed` or the Docker path: `python regenerate_skin_cache.py --upload server/skins/pool/my_skin.png`
   (variant detected from the PNG or taken from catalogue.json; `--variant slim` to force).
3. `python tools/skins/build_pool.py --catalogue-only` (pool skins only; procedural/default
   entries are regenerated by build_pool.py, other files in pool/ are not listed - add them
   to the catalogue by hand with `"source": "custom"` and include that source in `skin_sources`).

On the Docker path, `generate_compose.py` checks that every **top-level** `.png` has a `.customskin`
(`python3 regenerate_skin_cache.py --upload server/skins` signs the two session skins). The native
runners do not need one.

## Runtime flow

1. `run_windows.py` / the compose `prep_data` service copies this directory to `<server>/skins/`.
2. `episode start ... session_a.png ... session_b.png` applies the session skins: signed when a
   `.customskin` exists, otherwise as local skins.
3. Per episode, `/episode skin` (local mode) sets the unsigned local property on the bot and
   its camera with Paper's `setPlayerProfile`, which re-sends the player to all viewers; the
   camera mod loads `<repo>/server/skins/pool/<id>.png` (launcher `--skins-dir`).
   Signed mode: reads `<server>/skins/pool/<id>.png.customskin`, stores it in SkinsRestorer
   (custom key `file_<name>` on Windows, `file:<name>` elsewhere) and applies it; camera
   clients load that texture from their skin cache (`seed_client_cache.py`) or download it.

## Troubleshooting

- A camera shows Steve/Alex/... instead of the chosen skin: local mode - check
  `local_skins.skins` in `camera_<bot>_meta.json` (`status: missing` = the PNG is not in
  `--skins-dir`); signed mode - the client could not download the texture (2 s HTTP read
  timeout), run `seed_client_cache.py`.
- `{"ok":false,"error":"missing .customskin ..."}` (signed mode): run `regenerate_skin_cache.py --upload` for that PNG.
- `regenerate_skin_cache.py` waits a long time: the MineSkin hourly limit; it resumes where it
  stopped, or set `MINESKIN_API_KEY`.

## `.customskin` format

```json
{"skinName": "proc_0001.png", "value": "<base64 textures property>", "signature": "<base64 Mojang signature>",
 "dataVersion": 1, "variant": "classic", "texture_url": "http://textures.minecraft.net/texture/...",
 "texture_hash": "...", "png_sha256": "...", "mineskin_uuid": "...", "generated_utc": "...", "verified_pixels": true}
```
